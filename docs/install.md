# SynoFind 手动安装说明

> **历史版本说明：** 本文仅适用于 SynoFind 0.1.0 独立索引 `.spk` 套件。当前主路线已改为无需在 NAS 安装套件的官方 API 直连客户端，请先阅读 [Python 客户端说明](../clients/python/README.md)。旧包与源码继续保留；以下安装流程不适用于新客户端。

目标设备：DS918+（Apollolake / x86-64），DSM 7.1.1-42962 Update 9。首版安装包不代表其他机型或 DSM 版本已通过验证。

## 1. 安装

在 Windows 上准备 `SynoFind-apollolake-0.1.0.spk` 和随附 `.sha256` 文件。可先用 PowerShell 检查文件：

```powershell
Get-FileHash -Algorithm SHA256 .\SynoFind-apollolake-0.1.0.spk
```

结果应与校验文件一致。然后：

1. 登录当前群晖 DSM。
2. 打开「套件中心 → 手动安装」，选择 `.spk`。
3. 阅读 DSM 的第三方套件提示。此包是自行开发的第三方包，没有群晖官方签署或商店审核；确认自己选中了本项目交付的文件后，由你决定是否继续。
4. 在安装向导设置独立的 SynoFind 登录密码（至少 12 个字符，UTF-8 编码不超过 72 字节）和端口（默认 `8787`，范围 `1024–65535`）。不要复用 DSM 管理员密码。
5. 完成安装并启动套件。

安装过程不下载任何运行时依赖，不修改 DSM 版本，也不需要 Docker。重新安装保留的数据时，使用原密码和端口；安装向导中的新值不会覆盖原配置。升级无需重新输入密码。

## 2. 只读目录权限

第一次安装后，SynoFind 套件账户可能还不能读取资料。此时套件可以运行，索引页会显示权限错误。

1. DSM「控制面板 → 共享文件夹」选择 `Wonvy`。
2. 点击「编辑 → 权限」，将用户类别切换为「系统内部用户」。
3. 找到 `synofind`，授予 **只读** 权限并保存。
4. 如果某些子目录有单独设置的 ACL，确认它们也允许 `synofind` 读取；不要为了修复搜索而给套件管理员权限或把整个共享目录设为所有人可写。
5. 返回 SynoFind，点击“刷新索引”。

页面设置默认资料路径 `/volume1/Wonvy`，Windows 共享路径 `\\10.0.0.10\Wonvy`。如果实际资料在其他存储空间，在 SynoFind 设置中填写正确路径；保存时会检查目录是否存在、能否读取。源目录配置应只包含你希望通过网页和 API 访问的个人资料。

## 3. 打开网页与调用 API

套件中心点击“打开”，或者在 Windows 浏览器访问 `http://10.0.0.10:8787/`（自定义端口时替换 `8787`）。使用安装向导中设置的密码登录。

首次索引期间，可查看已扫描数量、耗时和错误。后续每 15 分钟触发扫描；同时最多运行一次扫描。文件很多时，实际更新延迟包含扫描耗时。

在设置页创建 API 令牌。令牌只显示一次，请保存到本地密码管理器或应用的安全配置中。令牌可搜索、读取文件和触发索引，不具备网站设置或令牌管理权限；删除令牌后立即失效。调用方式见 [API 文档](api.md)。

网页下载获得文件副本；“复制共享路径”可用于 Windows 资源管理器访问原文件。浏览器不能默认在本机软件中原地编辑群晖文件。

默认端口提供 HTTP，仅适合可信局域网；HTTP 不加密密码、会话或令牌。不要直接映射公网端口。本版只验收直接访问：启用 HTTPS 反向代理前，还需要适配可信代理、外部地址及会话来源校验，不能仅加一条代理规则就认为兼容。后续使用 HTTPS 时应配置受信任证书，不要在调用代码中关闭证书验证。

## 4. 升级、停止与卸载

- **停止/启动**：在套件中心操作。停止会结束扫描和 HTTP 服务；再次启动使用已有配置与索引，并重新扫描。
- **升级**：手动安装更高构建号的 `.spk`。程序目录会替换，账号、令牌、配置及索引保留。升级前建议备份套件数据；不要直接拷贝正在写入的 SQLite 文件。
- **卸载**：程序和套件服务被移除，配置及索引默认保留。原始资料始终保留；重新安装相同包身份后可继续使用已有账号。
- **数据位置**：`/var/packages/synofind/var` 指向 DSM 管理的持久化数据目录；内有配置、索引等。不要将此目录放入搜索范围，也不要把配置文件发给别人，它包含密码哈希等安全信息。

## 5. 实机验收清单

以下需要在安装后的 DS918+ 上确认，不能仅凭安装包静态检查标记通过：

- 安装向导正确显示密码和端口输入，套件可以启动。
- 授予只读权限后，`Wonvy` 首次扫描成功，并记录实际数量与耗时。
- 搜索一个已知文件，验证名称、相对路径、大小和修改时间。
- 下载该文件，与原文件内容一致；API 用新令牌下载同一文件成功。
- 图片/PDF/文本预览正常；不支持的格式可以下载。
- 在测试子目录创建、改名、删除测试文件，手动刷新后结果对应变化。
- 撤销测试令牌后请求返回 `401`。
- 在套件中心停止后网址不可访问，启动后仍可登录、搜索。
- 更高构建号升级后配置、账号和令牌仍在。

不要为了验收而修改重要资料；新增、删除测试仅在你指定的临时子目录内进行。

## 6. 故障定位

| 现象 | 检查内容 |
|---|---|
| 显示套件不兼容 | 确认型号架构与 DSM 版本；此包针对 Apollolake。 |
| 安装或启动失败 | 查看套件中心提示及 `/var/log/packages/synofind.log`、`/var/log/synopkg.log`。端口可能被占用。 |
| 网页打不开 | 确认套件运行、IP/端口正确，以及既有 DSM 防火墙允许你的局域网电脑访问该端口。 |
| 索引权限不足 | 按第 2 节配置系统内部用户 `synofind`，检查子目录 ACL。 |
| 部分结果未及时更新 | 查看索引运行状态和最后完成时间，手动刷新；扫描失败时旧记录会保留。 |
| 文件已移动或删除 | 刷新索引。文件记录不等于原文件永久存在，下载会重新检查。 |
| 升级后打不开 | 停止/启动套件，查看启动日志；不要删除持久化数据来“修复”。 |

如已有 SSH 维护通道，可以检查用户服务 `pkguser-synofind.service` 的日志；正常安装和使用不要求开启 SSH。分享故障信息时仅提供错误及版本，不提供密码、令牌或完整配置文件。
